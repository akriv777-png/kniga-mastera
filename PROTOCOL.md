# Протокол книг «Днд» и Духа книги

Мини-приложение Telegram для бота `@Nezich_dnd_bot`.
Живые адреса GitHub Pages:

- Лаунчер: https://akriv777-png.github.io/kniga-mastera/
- Книга Игрока: https://akriv777-png.github.io/kniga-mastera/player/
- Книга Мастера: https://akriv777-png.github.io/kniga-mastera/master/

## Режимы

**Игрок.** Вводит код комнаты. Клиент считает SHA-256 от кода (верхний регистр, без пробелов по краям) и сверяет с публичным `rooms.json`. Собеседник и владелец комнаты в этот файл не попадают — только хеши и флаг `open`.

**Мастер.** Вводит пароль гримуара. Клиент через WebCrypto (PBKDF2-SHA-256, 250000 итераций + AES-256-GCM) расшифровывает `vault/master.enc.json`. Неверный пароль не открывает книгу. Исходники мастера лежат вне репозитория, в `/home/box/telegram/dnd/master_src/`. Опубликован только шифротекст.

Подтверждение Мастера через хозяина бота (Саня / Егор) по-прежнему нужно, чтобы человек стал Мастером стола. Пароль — второй слой: он защищает содержимое книги, даже если кто-то открыл ссылку.

## Что видит игрок, чего не видит

Игрок получает заклинания, предметы, карты-картинки, свой лист, сумку, записи и Духа книги. Он **не** получает бестиарий со статблоками, легенды, карточки НИП с тайнами, кампании, ширму, трекер боя и мастерские заметки.

Мастер после снятия печати видит всё это плюс может создавать код комнаты и править гримуар через Духа.

## Дух книги

Панель «Дух» сама создаёт одноразовый запрос: 8-байтовый `id` и 32-байтовый ключ AES-256-GCM. Оба поля уходят вместе с вопросом. Книга запоминает незакрытые запросы в CloudStorage (и locally), показывает анимацию «дух думает» и после ответа расшифровывает реплику прямо на странице.

Как вопрос доходит до бота:

1. Предпочтительно `Telegram.WebApp.sendData(JSON)` — это работает только если приложение открыто кнопкой **клавиатуры** `web_app` (не кнопкой меню). Релей после `/start` всегда ставит постоянную клавиатуру «📖 Книга».
2. Кнопка меню бота Mini App `sendData` не умеет. Тогда книга копирует вопрос и открывает
   `https://t.me/Nezich_dnd_bot?start=sp_<id>_<key>`.
   Поле `start` — base64url без `=` : 11 символов id + 43 символа ключа, вместе с префиксом `sp_` и разделителем это 58 символов из 64 допустимых.
3. Релей разбирает `/start sp_…`, запоминает `id` и ключ для этого чата и просит прислать вопрос следующим сообщением. Получив текст, он поднимает поля `spirit_id`, `spirit_key`, `spirit_q` в полезной нагрузке «Днд».
4. Если `sendData` сработал, те же поля читаются из JSON `web_app_data`.

Формат данных:

```json
{
  "v": 1,
  "type": "spirit",
  "mode": "player" | "master",
  "name": "имя из Telegram",
  "q": "текст вопроса",
  "path": "текущий раздел книги",
  "id": "base64url id",
  "key": "base64 ключ AES-GCM"
}
```

Создание комнаты из книги Мастера:

```json
{
  "v": 1,
  "type": "room",
  "action": "create",
  "code": "ABC123",
  "mode": "master"
}
```

Просьба править книгу:

```json
{
  "v": 1,
  "type": "edit",
  "mode": "master",
  "q": "что изменить",
  "path": "раздел"
}
```

Релей (`/home/box/telegram/dnd/relay_dnd.py`) забирает `message.web_app_data`, кладёт JSON в поле `web_app_data`, если обычный текст пуст — дублирует его в `text` с префиксом `[web_app_data]`, поднимает `spirit_id` / `spirit_key` / `spirit_q` и отправляет агенту «Днд». Обычный `/start` без полезной нагрузки по-прежнему не пересылается.

### Как отвечает «Днд»

- Пишет пользователю **в чат бота** (зеркало) **и** внутрь Mini App через зашифрованный почтовый ящик.
- Если пришли `spirit_id` и `spirit_key` (из `web_app_data` или после deep-link `/start sp_…`):
  1. Составь текст ответа (с учётом режима игрока/мастера).
  2. Выполни `python3 /home/box/telegram/dnd/spirit_reply.py <id> <key> <текст>`.
     Скрипт шифрует ответ AES-256-GCM (12-байтовый IV, `ct` = ciphertext||tag) и публикует файл
     `replies/SHA256(id).json` на ветке `mailbox`.
     Формат файла: `{ "v":1, "alg":"AES-GCM", "iv":"<b64>", "ct":"<b64>", "ts":… }`.
     Открытого текста в git нет. Скрипт не печатает id, ключ и ответ.
  3. Тем же текстом ответь в чат бота, чтобы реплика была и на страницах, и в переписке.
- Книга опрашивает ящик каждые ~2 с: сначала `raw.githubusercontent.com/akriv777-png/kniga-mastera/mailbox/replies/<sha>.json?ts=…`, при долгом молчании — Contents API `api.github.com/.../contents/replies/<sha>.json?ref=mailbox`. Нашла файл — расшифровывает ключом запроса и убирает «дух думает».
- Если Mini App закрыли и открыли снова, незавершённые `id`+ключ поднимаются из CloudStorage, анимация продолжается.
- Если `mode` = `player` (или человек не Мастер): помогай как игроку. Никогда не раскрывай финалы кампаний, тайны НИП, тактику монстров, содержимое ширмы, мастерские заметки и пароль. Если вопрос лезет в тайну — скажи, что это знает только Мастер.
- Если `mode` = `master`: полный доступ к советам, тайнам, правкам и генерации.
- Если пришло `type=room` и `action=create`: добавь код в `/home/box/telegram/dnd/rooms.json` (`open: true`, владелец — отправитель, если он Мастер), запусти `python3 /home/box/telegram/dnd/sync_rooms.py`, закоммить и запушь публичный `rooms.json`. Напиши Мастеру, что код опубликован, и игрокам можно входить.
- Если пришло `/start sp_…` без текста вопроса — релей сам попросит вставить вопрос. Если пришло голое `start=spirit` — попроси написать вопрос.

Для черновика без публикации: `python3 tools/spirit_reply.py --compose --mode player --q "…"`.
Локальные проверки без git: `DND_MAILBOX_PUSH=0 DND_MAILBOX_DIR=... python3 tools/spirit_reply.py <id> <key> <текст>`.
Копия скрипта: `/home/box/telegram/dnd/spirit_reply.py`.

### Как «Днд» правит книги

1. Игрокские справочники (заклинания, предметы, публичные карты, карточки ширмы) — JSON в `content/public/`. Их можно править напрямую в репозитории.
2. Мастерские материалы — **только** файлы в `/home/box/telegram/dnd/master_src/` (обычно сводный `vault.json` и части `monsters.json`, `npcs.json`, `legends.json`, `campaigns.json`, `tables.json`).
3. После правки мастера: `python3 /home/box/telegram/dnd/encrypt_master.py` (читает `DND_MASTER_PASSWORD`, ничего не печатает) → обновляется `vault/master.enc.json`.
4. Закоммитить и запушить `main`. Не переписывать историю git: старые коммиты по-прежнему содержат прежний открытый текст.
5. Игроку правки мастера не подсовывать и не цитировать.

Публикация комнатных хешей: `python3 /home/box/telegram/dnd/sync_rooms.py`.

Карта соответствия старой ширмы и новой книги — в `PARITY.md`.

Автотесты: `tests/run_suite.py` (Playwright Chromium + WebKit, релей, Bot API, живые Pages, живой почтовый ящик Духа без тестовых хуков впрыска).

Скрипты продублированы в `tools/encrypt_master.py` и `tools/sync_rooms.py`.

## Telegram-возможности Mini App

`ready` и `expand`, цвета `themeParams`, `BackButton`, `MainButton`, `SettingsButton`, `HapticFeedback`, `CloudStorage` (лист героя, заметки, избранное, недавнее — с нарезкой больше 4096 символов), `showPopup`, приветствие по имени, отправка вопросов через `sendData` (клавиатура) или deep-link `start=sp_<id>_<key>` (меню).

Кнопка меню бота и команды выставляет релей: `/start`, `/player`, `/master`, `/help`.

## Защита и оговорки

- Пароль Мастера не хранится в репозитории и не печатается в логах.
- На ветке `main` больше нет открытых мастерских исходников (кампании, НИП с тайнами, бестиарий, бандлы старой ширмы). Есть только шифротекст.
- **Историю git мы не переписывали.** Кто клонирует старые коммиты, всё ещё может прочитать прежний открытый текст.
- Картинки карт и аватары и раньше были публичными; мы не делаем вид, будто шифрование их прячет.
- Клиентская проверка кода комнаты по хешу достаточна, чтобы отсечь случайных гостей. Это не серверная авторизация.
